# Evolutionary Trading Agents

No gradient descent. No backprop. No loss function. This project evolves trading agents
the same way nature evolves instinct: generate a bunch of randomly-weighted agents, throw
them into the market, kill the ones that go broke, breed the survivors, repeat.

The idea behind it: a fawn doesn't *learn* to run from a lion by nearly dying once — the
"training" already happened, across thousands of generations of ancestors who didn't run
and didn't reproduce. The instinct is baked into the weights (genes) before birth. This
project tries the same trick on a trivial trading problem — instead of training one model
with gradients, run a population, let survival + reproduction do the optimization, and see
if competent behavior emerges without ever computing a gradient.

## How it works

**Agents.** Each agent is nothing but 7 floating-point weights and a name. There's no
neural net, no training loop — just a dot product:

```
score = Σ (input_i * weight_i)
```

where the 7 inputs are a 5-step rolling window of prices plus the agent's current cash
and current stock holdings. If `score > 0.1` the agent buys, if `score < -0.1` it sells
(if it's holding anything), otherwise it holds.

**Reproduction, not training.** Weights are never adjusted by gradient — they're set once
at random (`create()`), and the only way they improve is:

1. Run every living agent against the price series.
2. Rank survivors by final net worth.
3. Take the top 2 survivors, average their weight vectors element-wise, add a small
   Gaussian perturbation (`σ = 0.02`) — that's the child.
4. Refill the population back up to `target_population` with children of the top 2.
5. Repeat for `total_generations`.

Nothing here is differentiated. It's closer to a (very stripped-down) genetic algorithm
than to machine learning in the usual sense — selection and averaging replace the
optimizer.

**Why agents die, and why that's the point.** Every step costs `0.05` in cash regardless
of what the agent does — modeled as a running "infrastructure / compute cost." Without
this, an agent that has learned nothing and simply never trades survives forever with its
initial \$1000, and "hold forever" would be a stable, undeserving winner. The constant
decay forces every agent to actually trade to stay solvent, which is what makes the
survivor pool meaningful. Agents can die two ways:

- `DEATH_INFRA_COST` — cash went negative just from the passive decay.
- `DEATH_BANKRUPT` — the agent tried to buy a share it couldn't afford.

**The market.** `synthetic_stock_prices.txt` isn't real ticker data — it's generated by
`sythetic data.py`:

```python
prices = 100 + (0.05 * t) + (15 * np.sin(t / 25)) + np.random.normal(0, 0.2, steps)
```

A slow linear uptrend, a smooth cyclical wave, and a small amount of noise on top, with a
fixed seed (42) for reproducibility. This was a deliberate choice over pulling real
tickers: real prices carry the fingerprints of news, earnings, and one-off shocks that no
7-weight linear agent could ever pick up on from price alone, and training against that
noise would just be rewarding agents for overfitting events they have no signal for. The
synthetic series is patterned enough to reward genuinely reading the trend/cycle, and
random enough that agents can't just memorize a lookup table — but nothing in it is a
substitute for scale; it's 1000 points standing in for the 1000-ticker dataset that wasn't
available.

## Files

| File | Purpose |
|---|---|
| `New_idea.py` | The evolutionary pipeline: agent creation, reproduction, simulation, and the generation loop. Run this. |
| `sythetic data.py` | Generates `synthetic_stock_prices.txt`. Re-run to get a fresh (seeded) price series. |
| `synthetic_stock_prices.txt` | 1000-point synthetic price series consumed by every agent each generation. |
| `simulation_output/` | Created by `New_idea.py` on run — see below. A sample run is included so you can see the shape of the output without running it yourself. |

### `simulation_output/` (produced by a run)

- **`agents_json/<agent_name>.json`** — one file per agent that has ever lived, updated
  every generation it participates in: status (`survived`/`dead`), final net worth, cash,
  stock holdings, and the full per-step action log (`BUY`/`SELL`/`HOLD`/`DEATH_*`) for
  that generation.
- **`compressed_simulation_logs.csv`** — every logged action from every agent across all
  generations, concatenated into one CSV (columns: `step`, `price`, `action`, `cash`,
  `stocks_owned`, `score`, `model_name`, `generation`).

### Registry files (working state, written to the project root while running)

- **`model_registry.json`** — the current population: `alive_models` (names) and
  `weights` (name → 7-value weight vector).
- **`lineage_registry.json`** — every reproduction event: child name, both parents' names
  and weights, and the resulting child weights. This is the closest thing the project has
  to a "family tree."

## Running it

```bash
python "sythetic data.py"     # (re)generate the price series
python New_idea.py            # run the evolution — default: 100 generations, population 8
```

Tune the run in the `__main__` block:

```python
evolve_pipeline(total_generations=100, target_population=8)
```

At the end, the best net-worth agent ever seen across all generations (the "ultimate
champion") has its weights copied into the slot `"Agent 2"` in `model_registry.json`, so
the winning strategy is easy to find and reuse without digging through every generation.

## Caveats / things to be upfront about

- This is a **closed, single-asset, no-fees, no-slippage** toy market. It says nothing
  about whether this approach would survive contact with real trading conditions.
- Fitness is judged on a single price series, so there's a real risk of the population
  overfitting to the particular shape of this one synthetic trend/cycle rather than
  learning something general about trading.
- The population is tiny (8) and the genome is tiny (7 numbers) — this is a proof of
  concept for the "selection instead of gradients" idea, not a serious strategy search.
